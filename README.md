# Sniper Agent — этап 1

Мониторинг твитов KOL → извлечение адреса контракта → алерт в Telegram.

На этом этапе намеренно **нет обогащения данными** (капитализация, ликвидность,
холдеры) и **нет rug-чеков** — это этап 2. Сейчас задача одна: убедиться, что
цепочка «твит → алерт» работает стабильно и укладывается в несколько секунд.

## Как это устроено

```
twitterapi.io stream ──webhook──▶ FastAPI ──▶ Pipeline
                                               │
                          parser (base58 + regex + ссылки)
                                               │
                           dedup (Redis: твит + счётчик авторов)
                                               │
                                    Telegram (aiogram)
```

## Первая настройка (делается один раз)

```bash
cp .env.example .env      # заполнить ключи
openssl rand -hex 32      # положить в WEBHOOK_SECRET
```

Нужны четыре ключа: `TWITTERAPI_KEY`, `WEBHOOK_SECRET`, `TELEGRAM_TOKEN`,
`TELEGRAM_CHAT_ID`. Пятый, `ANTHROPIC_API_KEY`, необязателен — без него
бот работает, но шлёт все срабатывания парсера без разбора.

`TELEGRAM_CHAT_ID` — это **твой** чат, а не id бота. Напиши боту `/start`
и возьми id из `https://api.telegram.org/bot<ТОКЕН>/getUpdates`.

## Запуск после каждой перезагрузки

Четыре шага. Третий и четвёртый — единственные, где нужна голова.

**1. Docker.** Запустить Docker Desktop, дождаться, пока поднимется движок
(проверка: `docker info` отвечает без ошибки), затем:

```bash
docker compose up -d
curl http://127.0.0.1:8080/healthz     # ждём {"status":"ok"}
```

**2. Туннель.** Приложение слушает только `127.0.0.1`, наружу его надо
вывести:

```bash
cloudflared tunnel --url http://localhost:8080
```

Окно не закрывать — туннель живёт, пока работает процесс.

**3. Адрес в кабинет.** Туннель напечатает адрес вида
`https://что-то.trycloudflare.com`. Он **меняется при каждом запуске**.
Открыть кабинет twitterapi.io, Tweet Filter Rules, и вписать в поле
Webhook URL:

```
https://<новый-адрес>/webhook/<WEBHOOK_SECRET>
```

Секрет — целиком из `.env`. Забыть этот шаг — самая частая ошибка: бот
будет работать, а твиты не придут.

**4. Правило.** Оно живёт на серверах twitterapi.io и переживает
перезагрузку, так что обычно достаточно проверить:

```bash
python tools/rules.py list
```

Если правила нет или список аккаунтов в `config/kols.yml` менялся:

```bash
python tools/rules.py sync
```

## Выключение

Правило продолжает работать и **тратить деньги**, пока компьютер выключен:
оно живёт не у тебя. Перед долгой паузой:

```bash
python tools/rules.py off      # обратимо, потом on
```

Контейнеры и туннель гасить не нужно — они умрут сами.

## Проверка, что всё живо

```bash
docker compose ps                          # оба контейнера Up
docker compose logs sniper --tail 20       # ошибок нет
python tools/rules.py list                 # правило ВКЛ
```

В выводе `list` смотри на `last_tweet_id`. Если правило включено, а там
по-прежнему `0` — оно ничего не обработало, и дело не в твоём коде:
проверяй подписку и webhook URL в кабинете.

Внешние доставки в логах видны как `POST /webhook/...` с чужого адреса.
Строки с `172.18.0.1` — это локальные тесты, а не настоящие твиты.

## Что проверить перед боем

1. **Поля ответа API.** Вся привязка к формату twitterapi.io собрана в
   `normalize_tweet()`. Сверь имена полей с их доками — API живой.
2. **Задержка.** В каждом алерте печатается `latency`. Если стабильно больше
   5–10 секунд — стрим отваливается, смотри логи.
3. **Ложные срабатывания.** Первую неделю гоняй в отдельный тестовый чат и
   веди список мусорных адресов — пополняй `DENYLIST` в `parser.py`.
4. **Ретвиты** сейчас отбрасываются, реплаи — нет (под анонсами часто кидают
   CA именно в реплае). Если реплаи зашумляют — правится в `pipeline.py`.
