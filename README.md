# Sniper Agent — этап 1

Мониторинг твитов KOL → извлечение адреса контракта → алерт в Telegram.

На этом этапе намеренно **нет обогащения данными** (капитализация, ликвидность,
холдеры) и **нет rug-чеков** — это этап 2. Сейчас задача одна: убедиться, что
цепочка «твит → алерт» работает стабильно и укладывается в несколько секунд.

## Как это устроено

```
twitterapi.io stream ──webhook──▶ FastAPI ──▶ Pipeline
                                               │
                          parser (base58 + regex + ссылки)
                                               │
                           dedup (Redis: твит + счётчик авторов)
                                               │
                                    Telegram (aiogram)
```

## Запуск

```bash
cp .env.example .env      # заполнить ключи
openssl rand -hex 32      # положить в WEBHOOK_SECRET
docker compose up -d
```

Вебхук должен быть доступен извне по HTTPS. Проще всего Caddy перед контейнером:

```
sniper.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Затем зарегистрировать аккаунты в стриме, передав URL
`https://sniper.example.com/webhook/<WEBHOOK_SECRET>` — см.
`TwitterApiIoClient.register_stream`.

Для локальной отладки без публичного домена сгодится `cloudflared tunnel`.

## Что проверить перед боем

1. **Поля ответа API.** Вся привязка к формату twitterapi.io собрана в
   `normalize_tweet()`. Сверь имена полей с их доками — API живой.
2. **Задержка.** В каждом алерте печатается `latency`. Если стабильно больше
   5–10 секунд — стрим отваливается, смотри логи.
3. **Ложные срабатывания.** Первую неделю гоняй в отдельный тестовый чат и
   веди список мусорных адресов — пополняй `DENYLIST` в `parser.py`.
4. **Ретвиты** сейчас отбрасываются, реплаи — нет (под анонсами часто кидают
   CA именно в реплае). Если реплаи зашумляют — правится в `pipeline.py`.
